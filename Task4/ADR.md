### <a name="_b7urdng99y53"></a>**Название задачи:**

Передача ставок в кол-центр
### <a name="_hjk0fkfyohdk"></a>**Автор:**

Разработчик IT отдела
### <a name="_uanumrh8zrui"></a>**Дата:**

25.05.2025
### **Функциональные требования**

| №   | Действующие лица или системы | Use Case               | Описание                                                                                    |
| --- | ---------------------------- | ---------------------- | ------------------------------------------------------------------------------------------- |
| 1   | Основной кол-центр           | Получение ставок       | Система кол-центра должна получать актуальные ставки по депозитам из системы ставок         |
| 2   | Партнёрский кол-центр        | Экспорт ставок         | Система ставок должна формировать файлы со ставками и передавать их в партнёрский кол-центр |
| 3   | Оператор кол-центра          | Просмотр ставок        | Операторы должны иметь доступ к актуальным ставкам в интерфейсе системы                     |
| 4   | Система мониторинга          | Отслеживание изменений | Система должна отслеживать успешность синхронизации ставок                                  |
### **Решение**

#### Диаграмма контекста
```mermaid
C4Context
    title Контекстная диаграмма интеграции системы ставок

    Person(client, "Клиент", "Звонок в кол-центр")
    Person(operator, "Оператор колл-центра", "Консультация по ставкам")
    Person(admin, "Администратор АБС", "Управление ставками")
    
    Enterprise_Boundary(bank, "Банковская система") {
        System(abc, "АБС", "Хранение и расчет депозитных ставок")
        System(rate_system, "Сервис экспорта ставок", "Преобразование и шифрование ставок")
        System(sftp_bank, "SFTP банка", "Хранение файлов для внутреннего колл-центра")
        System(crm_bank, "CRM система внутреннего колл-центра", "Отображение ставок операторам")

        Rel(client, operator, "Запрос ставок", "Телефонный звонок")
        Rel(operator, crm_bank, "Проверка ставок", "Web-интерфейс")
        Rel(admin, abc, "Обновление ставок", "Desktop клиент")

        Rel(abc, rate_system, "Передача данных", "JDBC")
        Rel(rate_system, sftp_bank, "Загрузка файла")
        Rel(rate_system, sftp_partner, "Отправка файла")
        Rel(sftp_bank, crm_bank, "Синхронизация данных")
    }
    
    Boundary(b3, "BankBoundary3", "boundary") {
        System_Ext(sftp_partner, "SFTP партнера", "Хранение файлов для внешнего колл-центра")
        System_Ext(crm_partner, "CRM система партнерского колл-центра")
        
        Rel(sftp_partner, crm_partner, "Передача данных")
    }

    Rel(client, operator, "Запрос ставок", "Телефонный звонок")
    Rel(operator, crm_bank, "Проверка ставок", "Web-интерфейс")
    Rel(admin, abc, "Обновление ставок", "Desktop клиент")
```
####  Диаграмма компонентов
```mermaid
C4Component
    title Диаграмма компонентов для интеграции системы ставок

    System_Boundary(bank, "Банковские системы") {
        Container_Boundary(АБС, "АБС", "Oracle", "Основное хранилище ставок") {
            Component(abc_rate, "Модуль ставок", "PL/SQL", "Расчет и хранение ставок")
            Component(abc_transaction, "Транзакционный модуль", "Delphi", "Обработка операций")
        }

        Container_Boundary(rate_system, "Сервис экспорта ставок", "Java 17 + Spring Boot") {
            Component(api, "REST API")
            Component(csv, "Генератор CSV")
            Component(pgp, "PGP-шифрование")
            Component(scheduler, "Планировщик")
        }

        Container_Boundary(SFTP_Server, "SFTP-сервер") {
            Component(store, "Хранилище")
            Component(auth, "Аутентификация")
        }
        
        System(crm_bank, "CRM банковского колл-центра")
    }

    System_Ext(crm_partner, "CRM партнера")

    Rel(abc_rate, api, "JDBC", "Периодический вызов")
    Rel(api, csv, "Преобразование данных")
    Rel(csv, pgp, "Шифрование")
    Rel(pgp, store, "Выгрузка данных")

    Rel(store, crm_bank, "Выгрузка данных")
    Rel(store, crm_partner, "Пуш данных")
```
### **Альтернативы**

- Полная интеграция через API для обоих кол-центров (отклонена из-за технических ограничений партнёрского кол-центра) 
- Использование промежуточного сервиса ETL (отклонена из-за дополнительных затрат)
- Ручная загрузка данных (отклонена из-за высоких рисков ошибок)
### **Недостатки, ограничения, риски**

- Зависимость от надёжности канала передачи файлов для партнёрского кол-центра
- Возможные задержки в обновлении данных из-за файловой синхронизации
- Необходимость дополнительной валидации данных при экспорте
- Сложность поддержки двух разных механизмов синхронизации
### **Список задач для реализации**

**Система ставок:**

- Разработка API для основного кол-центра
- Реализация модуля экспорта файлов
- Создание системы мониторинга синхронизации
- Внедрение механизма шифрования данных
- Разработка системы логгирования

**Основной кол-центр:**

- Интеграция с новым API
- Разработка интерфейса отображения ставок
- Настройка автоматического обновления данных

**Партнёрский кол-центр:**

- Настройка процесса приёма файлов
- Разработка механизма обновления данных
- Интеграция со своей CRM-системой

**Команда поддержки:**

- Разработка документации по интеграции
- Подготовка инструкций для операторов
- Организация тестирования
- Обеспечение технической поддержки
